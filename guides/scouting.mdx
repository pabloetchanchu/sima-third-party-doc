## Resumen

El módulo de **Monitoreo** de SIMA registra recorridas de campo: plagas, enfermedades, malezas, estados fenológico e hídrico, y medidas asociadas. Las integraciones de terceros **leen** esas sesiones; el alta se hace en la app web o móvil.

<Warning>
  **Monitoreo de campo** (`scouting`) y **monitoreo de silobolsa** (`silobag_scoutings`) son dominios distintos. Esta guía cubre solo scouting de lote/campaña. Para silobolsas ver [Silobolsas](/guides/silobags).
</Warning>

---

## Mapa de entidades

```
Catálogos globales (v2)
  Adversity Kind → Adversity Category → Adversity

Catálogos de estado (v3, solo lectura)
  hydric_states
  phenological_states  (por especie: cultivation_id)
  plot_states
  scouting_measures    (unidad de muestreo por tipo de adversidad)

Sesión de campo (v3)
  Scouting  →  campaign_id
            →  phenological_state_id, hydric_state_id, plot_state_id
            →  scouting_protocol_results (adversity_id, measure_id, valor, semáforo)
            →  scouting_sample_values / scouting_sample_alerts
```

---

## Paso 1 — Catálogo de adversidades (v2)

Antes de interpretar resultados de protocolo, sincronizá el catálogo de adversidades (solo lectura, global).

### Tipos (`adversity_kinds`)

Clasificación de primer nivel: Insectos, Enfermedades, Malezas, Medidas, etc.

```
GET /api/v2/third_party/adversity_kinds
```

**Filtros:** `name`, `modified_at_from`, `modified_at_to`, `deleted_at_from`

**Response:**

```json
{
  "items": [
    { "id": 2, "name": "Insectos", "modified_at": "2023-12-07T19:36:31-03:00", "deleted_at": null },
    { "id": 3, "name": "Enfermedades", "modified_at": "2023-12-07T19:36:31-03:00", "deleted_at": null },
    { "id": 4, "name": "Medidas", "modified_at": "2023-12-07T19:36:31-03:00", "deleted_at": null }
  ]
}
```

### Categorías y adversidades

```
GET /api/v2/third_party/adversity_categories
GET /api/v2/third_party/adversity
```

**Filtros de adversidad:** `name`, `scientific_name`, `adv_category_id`, `modified_at_from`

**Response (adversidad):**

```json
{
  "items": [
    {
      "id": 12,
      "adv_category_id": 3,
      "name": "Bicho bolita",
      "scientific_name": "Armadillium vulgare",
      "description": "Soil pest that attacks seedlings at hypocotyl level...",
      "modified_at": "2021-06-25T00:00:00-03:00"
    }
  ]
}
```

El catálogo cambia poco: sincronizalo al arranque o semanalmente con `modified_at_from`.

## Paso 1b — Catálogos de monitoreo (v3)

Estos IDs aparecen en cada sesión de scouting v3. Todos son **GET**, paginados con `page` / `size` y filtros de auditoría (`updated_at_from`, `active`, `deleted_at_from`, …).

### Estado hídrico

```
GET /api/v3/third_party/hydric_states
```

Campos: `id`, `name` (traducido), auditoría.

### Estado fenológico

```
GET /api/v3/third_party/phenological_states
```

Campos: `id`, `name`, `description`, `cultivation_id` (especie del catálogo), auditoría.

**Filtros propios:** `id`, `name`, `cultivation_id`.

Filtrá por especie para no mezclar etapas de soja con maíz:

```bash
GET /api/v3/third_party/phenological_states?cultivation_id=3&active=1
```

### Estado del lote

```
GET /api/v3/third_party/plot_states
```

Campos: `id`, `name`, auditoría.

### Medidas de scouting

Unidad y tipo de muestreo asociados a un `adversity_kind_id`. Los resultados de protocolo apuntan a `measure_id`.

```
GET /api/v3/third_party/scouting_measures
GET /api/v3/third_party/scouting_measures/{id}
```

**Filtros propios:** `id`, `adversity_kind_id`, `type`.

**Response (ítem de ejemplo):**

```json
{
  "id": 8,
  "adversity_kind_id": 2,
  "unit_sample": "individuos / m²",
  "type": "count",
  "created_at": "2023-12-07T19:36:31-03:00",
  "modified_at": "2023-12-07T19:36:31-03:00",
  "deleted_at": null,
  "active": true
}
```

## Paso 2 — Sesiones de scouting (v3)

Una sesión es una visita de campo sobre una **campaña**. Incluye estados, semáforo, muestras y resultados de protocolo (adversidades observadas).

<Warning>
  La API de Terceros expone scouting en **solo lectura** (GET). No hay POST/PATCH/DELETE para crear monitoreos desde integraciones externas.
</Warning>

```
GET /api/v3/third_party/scouting
```

**Filtros propios:** `id`, `campaign_id`.

**Filtros de auditoría:** `updated_at_from`, `deleted_at_from`, `active`, `page`, `size`.

**Response (campos principales de un ítem):**

```json
{
  "id": 293087,
  "observations": "Alta presión de áfidos en el sector NE",
  "campaign_id": 85973,
  "objective_yield_kg_ha": 4200,
  "phenological_state_id": 14,
  "hydric_state_id": 5,
  "plot_state_id": 2,
  "semaphore": 2,
  "samples_taken": 8,
  "knots": null,
  "estimated_yield": null,
  "plant_height": null,
  "scouting_protocol_results": [
    {
      "id": 55102,
      "adversity_id": 12,
      "protocol_id": 3,
      "measure_id": 8,
      "agg_result_value": 4.5,
      "semaphore": 2
    }
  ],
  "scouting_sample_values": [],
  "scouting_sample_alerts": [],
  "created_at": "2024-04-01T11:02:34-03:00",
  "modified_at": "2024-04-01T11:02:34-03:00",
  "deleted_at": null,
  "active": true
}
```

Cada `adversity_id` en `scouting_protocol_results` se cruza con el catálogo v2 (`GET /api/v2/third_party/adversity`). `measure_id` se cruza con `scouting_measures`.

### v2 (legacy)

```
GET /api/v2/third_party/scouting
```

Filtros: `campaign_id`, `modified_at_from`, `modified_at_to`, `deleted_at_from`, `page` / `size`.

La respuesta v2 es más plana (`adversity_ids[]`, `date_created`). Preferí **v3** para estados, protocolos y semáforo.

## Patrones de integración típicos

### SIMA → plataforma de analítica

1. Listá campañas (`GET /api/v3/third_party/campaigns`).
2. Consultá `GET /api/v3/third_party/scouting?campaign_id={id}&updated_at_from={last_sync}`.
3. Cacheá adversidades (v2), medidas y estados (v3) y resolvé los IDs en cliente.

### App de scouting → SIMA

La API de Terceros **no permite crear** sesiones. Opciones:

- Cargar el monitoreo en la app SIMA y sincronizar hacia tu sistema con GET
- Contactar [soporte@sima.ag](mailto:soporte@sima.ag) si necesitás escritura automatizada

---

## Frecuencia de sincronización

| Recurso | Frecuencia sugerida |
|---|---|
| Adversity kinds / categories / adversities | Semanal o al arranque |
| hydric_states, plot_states, scouting_measures | Semanal o al arranque |
| phenological_states | Semanal; filtrá por `cultivation_id` |
| Sesiones `scouting` | Cada 30–60 min en temporada activa, con `updated_at_from` |
